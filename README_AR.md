# Sport Performance — الإصدار 3.0

تطبيق مؤسساتي لإدارة التربية البدنية والأداء الرياضي، بواجهة عربية/فرنسية/إنجليزية واتجاه RTL/LTR، قابل للتثبيت كتطبيق PWA على الهاتف والحاسوب، مع مزامنة الحسابات والبيانات عبر Supabase.

> هذه حزمة مصدر ونشر. نجاح البناء المحلي لا يعني أن Supabase أو Cloudflare قد تم ربطهما بحسابك؛ يلزم تنفيذ خطوات الإعداد واختبار القبول بعد النشر.

## محتويات الحزمة

- `app/`: واجهة التطبيق، منطق التشغيل، التحقق من الإدخال، الحسابات المشتقة، وترجمات الواجهة الإضافية.
- `supabase/INSTALL_ALL.sql`: ملف SQL موحّد للتثبيت النظيف مرة واحدة، مع الاحتفاظ بالـ migrations الثلاث منفصلة للمراجعة والتتبع.
- `supabase/BOOTSTRAP_AR.sql`: إنشاء المؤسسة الأولى والسنة الأولى وربط مالك المنصة.
- `cloudflare-upload/`: أصول الموقع المبنية الجاهزة للرفع إلى Cloudflare Pages Direct Upload.
- `tests/`: اختبارات منطقية واختبارات بنيوية لسياسات SQL. هذه الاختبارات لا تستبدل تشغيل SQL على PostgreSQL أو اختبار RLS الحي.
- `docs/`: إعداد قاعدة البيانات، نموذج الأمان، مصفوفة الوظائف، نتائج QA، وتوثيق بروتوكول NAVETTE 20m.
- `scripts/build.mjs`: بناء مجلد النشر دون الاعتماد على حزم خارجية.
- `.env.example`: قيم توضيحية فقط بلا مفاتيح؛ التطبيق الثابت يحفظ URL وPublishable key من شاشة الإعداد على كل جهاز.

## 1. إنشاء Supabase

**استخدم مشروع Supabase جديدًا ونظيفًا لهذا المخطط.** ملفات `0001_clean_install.sql` وما بعدها ليست ترقية تلقائية لمخطط قديم. لا تشغّلها فوق مشروعك الحالي الذي يحتوي جداول قائمة قبل مراجعة مخططه واعتماد خطة ترحيل منفصلة.

1. أنشئ مشروع Supabase جديدًا.
2. افتح SQL Editor ونفّذ الملف `supabase/INSTALL_ALL.sql` مرة واحدة. هذا الملف يجمع migrations الثلاث بالترتيب. يمكنك بدلًا منه تنفيذ الملفات الثلاثة داخل `supabase/migrations/` بالترتيب، لكن **لا تنفذ الطريقتين معًا**. يجب إتمام التثبيت قبل إنشاء أي حساب.
3. بعد تنفيذ ملف التثبيت، أنشئ حساب المالك الأول من شاشة التسجيل في التطبيق مع ترك حقل رمز المؤسسة فارغًا، أو أنشئه من Authentication في Supabase. قبل وجود أي مؤسسة، يسمح trigger بإنشاء ملف أولي معلّق فقط.
4. افتح `supabase/BOOTSTRAP_AR.sql` واستبدل جميع القيم `*_HERE` بقيمك الحقيقية: بريد المالك، اسمه، اسم المؤسسة، slug فريد، اسم السنة الدراسية، وتاريخ بدايتها. نفّذ الملف مرة واحدة.
5. سجّل الدخول بحساب المالك. أنشئ المؤسسات الإضافية من صفحة الفريق والموافقات؛ بعد اعتماد مدير المؤسسة، ينشئ المدير السنة الدراسية الأولى من صفحة السنوات الدراسية.
6. يرسل مدير المؤسسة slug الخاص بها إلى المدربين والإدارة. ينشئون حساباتهم من التطبيق بهذا الرمز، وتبقى الحسابات معلّقة حتى يعتمدها مدير المؤسسة.
7. مالك المنصة يعتمد مديري المؤسسات فقط. مدير المؤسسة يعتمد أعضاء الإدارة والمدربين. لا يستطيع المستخدم اختيار دوره بنفسه.
8. في إعدادات Authentication، اضبط Site URL وRedirect URLs على نطاق التطبيق المنشور، واضبط رسائل تأكيد البريد واستعادة كلمة المرور وفق سياسة مؤسستك.

### ملاحظات Supabase

- المفتاح المسموح في المتصفح هو Publishable/anon فقط. لا تضع `service_role` في التطبيق أو `.env` أو ZIP.
- ينشئ migration الثانية bucket خاصًا باسم `sport-performance` ويضبط سياسات القراءة والرفع حسب المؤسسة.
- لا توجد بيانات طلاب أو نتائج أو BARÈME افتراضية. تُضاف الاختبارات الأساسية الأربعة فقط، أما المنشآت وسلالم التنقيط الرسمية فيدخلها المسؤول.
- لا يحتوي المخطط على جدول أو صفحة Audit Log.

## 2. تشغيل التطبيق محليًا

يتطلب Node.js 20 أو أحدث.

```bash
npm install
npm run check
npm test
npm run build
```

بعد البناء افتح `cloudflare-upload/index.html` عبر خادم محلي أو انشر المجلد. عند أول فتح، أدخل Project URL ومفتاح Publishable/anon. تحفظ إعدادات الاتصال محليًا على الجهاز؛ سجّل الدخول بالحساب نفسه على الهاتف والحاسوب لمزامنة البيانات عبر Supabase.

## 3. النشر على Cloudflare

### عبر لوحة Cloudflare

1. افتح **Workers & Pages → Create application → Pages → Direct Upload**.
2. أنشئ مشروع Pages جديدًا باسم مناسب مثل `sport-performance`.
3. ارفع محتويات مجلد `cloudflare-upload` (أو ZIP يحتوي محتوياته) كما هي.
4. بعد نجاح النشر، اربط النطاق من إعدادات Pages.
5. لا تستبدل Worker قديمًا أو مشروع `sportsuivi01` دون أن تقرر ذلك صراحة؛ هذا البناء موجّه إلى Cloudflare Pages Direct Upload.

### عبر Wrangler (اختياري)

```bash
npx wrangler pages deploy cloudflare-upload --project-name sport-performance
```

GitHub اختياري وليس شرطًا للنشر. تتضمن الحزمة `.github/workflows/quality.yml` لفحوصات تلقائية عند رفع الكود، و`deploy-pages.yml` للنشر اليدوي الاختياري بعد إضافة أسرار `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` إلى مستودع GitHub.

## 4. الوظائف المشمولة

- حساب مالك منصة، مؤسسات متعددة، مدير مؤسسة، إدارة، ومدربون بموافقات متدرجة مفروضة في SQL/RLS.
- إدارة التلاميذ والأقسام، رقم يدوي غير مقيد بصيغة محددة، تعديل بيانات التلميذ وأرشفته داخل السنة.
- لصق جماعي للتلاميذ من Excel/CSV مع معاينة وكشف التكرار والأقسام غير المعروفة.
- سنوات دراسية مستقلة، اختيار السنة، أرشفة السنة السابقة، ومنع التعديل عليها من التطبيق وقاعدة البيانات.
- حصص مرتبطة بالمدرب واسم المدرب المحفوظ ووقت البداية والنهاية والمدة، مع إغلاق الحصة مرة واحدة.
- حضور سريع بأرقام التلاميذ، حالات حاضر/غائب/متأخر، وأسباب الغياب: عادي/رخصة/إعفاء/واجب.
- تنبيه التأهيل بعد خمس غيابات PE متتالية، وظهوره عند العودة خلال حصتين فعليتين مكتملتين، مع المعالجة والتاريخ.
- اختبارات NAVETTE 20m وPompes وAbdominaux وBarre fixe/Perfix، وإضافة/تعطيل اختبارات أخرى.
- BARÈME خاص بكل مؤسسة، بإصدارات غير قابلة للتعديل بعد إنشائها، ولصق جماعي مع معاينة وتحقق. لا تُنشأ علامات افتراضية.
- إدخال الأداء الخام ومدة الاختبار، وسرعة NAVETTE عند توفرها رسميًا، وتحويل km/h إلى m/s وزمن قطع 20m والمسافة الكلية، ومعدلات التكرار/دقيقة والتكرار/ثانية ومتوسط زمن التكرار.
- استيراد جماعي للنتائج حتى 2000 صف في معاملة SQL واحدة، مع إعادة حساب العلامة والتحقق منها داخل قاعدة البيانات.
- تصحيح النتائج عبر RPC محمية، مع الحفاظ على إصدار BARÈME المناسب لتاريخ الاختبار.
- قياسات الوزن والطول وBMI وتاريخ القياسات واتجاه BMI.
- ملاحظات مشتركة للمؤسسة، وكراس خاص لكل مدرب مع عزل `owner_id`، وكلاهما مرتبط بالسنة.
- خطط ودروس الحصص ومرفقات PDF/Word/Excel/TXT في Storage خاص.
- منشآت وتجهيزات المؤسسة، وتفعيل/تعطيل الاختبارات.
- شعار المؤسسة وشعار العلامة المائية، منفصلان عن علامة التطبيق العامة.
- تقارير وملخصات الأقسام وتصدير CSV وطباعة التقرير.
- واجهة متجاوبة بثلاث لغات واتجاه RTL/LTR وPWA قابلة للتثبيت.

## 5. حدود يجب معرفتها

- يلزم اتصال بالإنترنت للوصول إلى Supabase وتحميل مكتبة Supabase JS من ESM CDN. يخزن Service Worker ملفات الواجهة، لكنه لا يوفّر كتابة بيانات Offline أو مزامنة مؤجلة دون اتصال.
- لا يحوّل التطبيق رقم Palier في NAVETTE تلقائيًا إلى سرعة ما لم تدخل السرعة الرسمية المعروفة؛ لا يخترع عدد الشاتلات أو جدولًا بروتوكوليًا غير موثق.
- حساب العلامات يتطلب إدخال BARÈME الرسمي للمؤسسة. إذا لم يوجد تطابق، يبقى الأداء الخام محفوظًا وتظهر حالة عدم التطابق بدل اختراع علامة.
- لا يمكن من هذه الحزمة إجراء اختبار حي لمشروع Supabase أو حساب Cloudflare الخاص بك؛ اختبر تسجيل الدخول، RLS، Storage، النطاق، والبريد بعد الإعداد. لا تستخدم هذه migrations النظيفة فوق قاعدة بيانات قديمة؛ يلزم قبل ذلك تصميم ترحيل مستقل مبني على مخططها الفعلي.

## 6. الاختبارات

- `npm run check`: فحص صياغة ملفات JavaScript.
- `npm test`: اختبارات الدوال الرياضية/الاستيراد واختبارات بنيوية لملفات SQL.
- `npm run build`: إعادة إنشاء `cloudflare-upload`.
- النتائج الفعلية وتفاصيل ما لم يُختبر حيًا في `docs/QA_RESULTS.txt` و`docs/PRODUCTION_CHECKLIST_AR.md`.

## دليل التشغيل اليومي

راجع `docs/USER_GUIDE_AR.md` لمعرفة ترتيب التهيئة وصيغ لصق التلاميذ والنتائج وBARÈME، وطريقة تسجيل الحضور وإنهاء الحصة، وآلية تنبيه التأهيل، وتصدير السنوات إلى Excel XLSX.
